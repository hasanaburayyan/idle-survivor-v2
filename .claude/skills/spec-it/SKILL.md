# Plan the spec

If the current repo does not have a directory called specs, ask the user where the spec should go.

## Design the spec

Ask the user for information on the feature that is being spec'd

Ensure to ask plenty of clarifying questions and dont make any nonsense assumptions.

## Store the spec
Ask the user what to name the spec.

Write the spec in the folder with other specs

## Implementaiton

Ask the user if they have read the spec and are willing to move forward with it (y/n/skip)

If the user skips, then this skill is done

if the user says no, ask what changes we would like to make or further instructions.

If yes, read the spec and move into plan mode for the implementation
